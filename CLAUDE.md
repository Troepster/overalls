# overalls

A Claude Code mod: one band above the prompt showing context-window "weather"
and the Ponytail level. Published to the Claude plugin directory from this
repo's `main` branch.

| File | What it is |
|---|---|
| `hooks/register.tsx` | The whole mod: hooks, rendering, Ponytail check |
| `hooks/register.test.ts` | Tests, run against the real engine |
| `types/index.d.ts` | `$.state` contract: every state key the module uses |
| `.claude-plugin/plugin.json` | Manifest, `userConfig` (the config page), listing fields |
| `.claude-plugin/marketplace.json` | Makes this repo installable as a marketplace |
| `.claude-plugin/types/` | Generated by Claude Code on load; gitignored. The authority on the mod API for the running build |

## Working on it

- Start sessions **in this folder**. `~/.claude/settings.json` sets
  `CLAUDE_CODE_PLUGIN_DIRS` to it, so the mod loads from here and every save
  hot-reloads it. Don't also install it from the marketplace: two bands.
- A reload re-runs `register` and `session.start`. Keep anything that must
  survive in `$.state` (the `atom`s at the top of `register.tsx`), declared in
  `types/index.d.ts`. Module variables start over.
- Before committing: `claude plugin validate .` and `claude plugin test .`.
  New behaviour gets a test; stub what the engine would answer with `on(...)`
  in the test (see existing tests for `session.usage`, `settings.read`,
  `fs.read`, `env.get`).

## Directory constraints (checked by the portal's Validate, not the local one)

- **No `options` on `userConfig` fields.** The directory blocks it, so Weather
  detail is a typed string, normalised against `DETAILS` in `register.tsx`
  and falling back to `full`. Use the same pattern for any new enum setting.
- **Keep `"types"` in `plugin.json`.** The portal warns it's unknown; local
  `claude plugin validate` needs it to check `$.state`.
- **README "Data and access" is the privacy policy** (`privacyPolicyUrl`
  points at it). Any new `$.fs`, `$.process`, network, settings or env call
  must be added there; the directory's security scan flags undisclosed
  behaviour.
- Hooks on events that share a name with a call (`prompt.submit`,
  `session.compact`) must be described in the README.

## Releasing

Every push to `main` is picked up by the directory within minutes (GitHub
webhook) and scanned. Once approved, passing versions auto-publish.

1. Work on a branch, never directly on `main`.
2. Bump `version` in `.claude-plugin/plugin.json`; the directory lists each
   release by it (the portal showed "New version detected v0.2.2").
3. Merge to `main` and push. Optionally tag `vX.Y.Z` and
   `gh release create`.

Submission page: claude.ai/directory/manage, plugin "Overalls".
